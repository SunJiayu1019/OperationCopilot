# Milestone 1 需求说明

## 1. 项目定位

OperationCopilot 面向内容运营人员，帮助其将零食商品图片转化为可用于小红书内容创作的候选文案，并通过平台规则与品牌规范完成风险提示和自动改写。

本阶段是可演示的 MVP 基础框架：业务流程、数据契约和页面闭环先跑通；模型、知识库和 Agent 决策在 Milestone 2/3 接入。

## 2. 范围边界

### In scope

- 平台固定为小红书。
- 商品类别固定为零食。
- 上传一张商品图片（PNG/JPEG/WebP，最大 10 MB）。
- 填写内容目标，提交一次分析任务。
- 展示任务的上传、分析、生成、审核、改写阶段。
- 展示模拟的商品信息、三版候选文案、风险项和合规改写结果。
- 为 MiniMind-V、Qwen、RAG 和 Agent 工作流保留明确的服务边界。

### Out of scope

- 真实模型调用、向量检索和知识库管理。
- 真实平台发布和账号系统。
- 多商品批量任务、复杂工作流编排、生产监控和高并发部署。
- 复杂测试体系与模型效果评估（归入后续里程碑）。

## 3. 目标用户与核心场景

用户是需要快速产出社交平台内容的商品/内容运营人员。典型任务是：上传一张零食商品图，说明希望强调的卖点，得到三种小红书风格草案；系统指出绝对化、无依据功效或品牌语气问题，并给出可直接继续编辑的改写版本。

## 4. MVP 用户故事与验收标准

### US-01 创建任务

作为运营人员，我可以上传商品图片并填写内容目标，以便提交一次小红书零食内容分析任务。

验收：未选择文件或文件类型/大小不符合限制时，表单阻止提交并在对应字段附近说明原因；合法提交后返回任务编号并进入结果视图。

### US-02 查看处理过程

作为运营人员，我可以看到任务处于哪个阶段，以便知道系统是否仍在工作。

验收：任务详情显示“素材分析、文案生成、内容审核、自动改写”四个阶段及当前状态；基础框架使用模拟处理结果，但状态结构可替换为异步 Agent 事件。

### US-03 查看内容结果

作为运营人员，我可以看到商品摘要、三版文案、风险提示和最终改写稿，以便选择和继续编辑内容。

验收：结果页至少展示商品属性、候选标题/正文/标签、风险级别与建议、改写前后对照；空结果和失败状态有清晰的恢复提示。

## 5. 非功能要求

- 页面支持键盘操作，表单控件有可见标签和错误关联。
- 移动端不产生横向滚动，主要触控目标不小于 44px。
- API 返回稳定 JSON 契约，错误包含可理解的原因。
- 本阶段默认本地运行，上传文件不持久化到数据库。
